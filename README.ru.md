# gpadmapper-cpp

Переназначение геймпада в Linux: правый стик — курсор, левый — прокрутка во
все стороны, кнопки настраиваются на кнопки мыши или сочетания клавиш. Один
небольшой демон на C++ (evdev + uinput): ~4 МБ RSS и 0 % CPU в простое.

Разработано под **8BitDo Ultimate 2C** на **Wayland (Wayfire/wlroots)**, но
работает с любым геймпадом, видимым через evdev, включая Xbox-пады и
PlayStation-контроллеры (DualShock 3/4, DualSense). Работает и на X11.

[English version](README.md)

## Чем отличается

- **Плавная прокрутка во все стороны.** В wlroots hi-res колесо часто
  квантуется клиентами до щелчков. Режим тачпада по умолчанию даёт
  непрерывный жест двумя пальцами, без «ступенек».
- **Нет ложного ПКМ.** Если поднять два виртуальных пальца одновременно,
  libinput видит двухпальцевый тап, а при `tap_to_click` (по умолчанию в
  Wayfire) это правый клик. Пальцы снимаются поэтапно.
- **Нет «инерции» в Chromium.** Chromium включает fling, если `axis_stop`
  приходит меньше чем через 200 мс после последнего движения. Демон держит
  жест неподвижным 300 мс, поэтому после отпускания стика страница не едет.
- **Пауза.** Зажать оба клика стиков на секунду — демон перестаёт что-либо
  нажимать, геймпад полностью свободен для игр. Ещё раз — продолжить.
- **Тишина в простое.** Таймер 250 Гц работает, только пока стик отклонён или
  идёт отсчёт комбо; иначе процесс спит в `ppoll`.
- **По умолчанию без grab.** Игры по-прежнему видят физический геймпад.

## Зависимости

- Linux с evdev и uinput
- `libevdev` (`libevdev-dev` в Debian/Ubuntu, `libevdev` в Arch)
- Компилятор с C++20 и `make`
- Чтение `/dev/input/event*` и запись в `/dev/uinput`. Обычно достаточно
  группы `input`:

  ```sh
  sudo usermod -aG input "$USER"   # затем перелогиниться
  ```

  Если в дистрибутиве нет правила для uinput:

  ```
  KERNEL=="uinput", GROUP="input", MODE="0660"
  ```

## Сборка и установка

### Одна команда

Нужны компилятор C++20, `make`, `pkg-config` и заголовки libevdev (см.
«Зависимости»). Команда скачивает исходники, собирает, ставит бинарник в
`~/.local/bin` и запускает systemd-сервис:

```sh
curl -fsSL https://raw.githubusercontent.com/Quieet88/gpadmapper-cpp/main/install.sh | sh
```

`PREFIX=/usr/local` — поставить в другое место. Без systemd шаг с сервисом
пропускается.

### Из исходников

```sh
make
make install            # ~/.local/bin (PREFIX=... чтобы изменить)
```

`sudo make install PREFIX=/usr/local` поставит в `/usr/local/bin`.

Первый запуск создаёт конфиг по умолчанию:

```sh
gpadmapper-cpp -v        # печатает найденное устройство и каждое нажатие
```

Если файла `~/.config/gpadmapper-cpp/config.toml` нет, демон создаст его сам.

### systemd (пользовательский сервис)

```sh
mkdir -p ~/.config/systemd/user
cp systemd/gpadmapper-cpp.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now gpadmapper-cpp
```

Unit рассчитан на бинарник в `~/.local/bin`. Если поставили в другое место,
поправьте `ExecStart=`.

## Привязки по умолчанию

| Вход                  | Действие                |
| --------------------- | ----------------------- |
| Правый стик           | Курсор                  |
| Левый стик            | Прокрутка (вверх/вниз/влево/вправо) |
| RT                    | ЛКМ                     |
| RB                    | ПКМ                     |
| MODE (кнопка 8BitDo)  | Super                   |
| START                 | Tab                     |
| SELECT                | Пробел                  |
| Крестовина            | Стрелки                 |
| A                     | Enter                   |
| B                     | Escape                  |
| X                     | Alt+Tab                 |
| THUMBL + THUMBR (1 с) | Пауза / продолжить      |

В паузе демон не шлёт вообще ничего: ни движения, ни прокрутки, ни клавиш.
Физический геймпад остаётся доступен играм при `grab = false`.

## PlayStation-контроллеры

Раскладка позиционная, поэтому имена выше общие с Xbox-падами:

| Имя в конфиге | Xbox | PlayStation |
| --- | --- | --- |
| `BTN_A` | A | Крест (Cross) |
| `BTN_B` | B | Круг (Circle) |
| `BTN_X` | X | Квадрат (Square) |
| `BTN_Y` | Y | Треугольник (Triangle) |
| `LB` / `RB` | LB / RB | L1 / R1 |
| `LT` / `RT` | LT / RT | L2 / R2 |
| `SELECT` / `START` | Back / Start | Create-Share / Options |
| `MODE` | Guide | Кнопка PS |
| `THUMBL` / `THUMBR` | L3 / R3 | L3 / R3 |

- **DualShock 4 / DualSense** отдают L2/R2 как `ABS_Z`/`ABS_RZ`; они работают
  как `LT`/`RT` без настройки.
- **DualShock 3** отдаёт L2/R2 цифровыми `BTN_TL2`/`BTN_TR2`; они тоже
  обрабатываются как `LT`/`RT`. Если пад отдаёт оба варианта, они объединяются,
  поэтому отпускание одного не отпускает другой.
- Крестовина приходит как `ABS_HAT0X/Y` (обычно у PS-падов) или как
  `BTN_DPAD_*` у некоторых клонов; поддерживаются оба, HAT имеет приоритет.
- Если подключено несколько падов, закрепите нужный через
  `[device] name = "DualSense"` (или другую подстроку имени evdev).
- Steam Input может подменить физический пад виртуальным Xbox-контроллером.
  Если кнопки ведут себя странно, отключите Steam Input для этого контроллера.
- У старых DS4 стики дрейфуют; при «ползущем» курсоре поднимите
  `[pointer] deadzone` до `0.10–0.15`.

Реальный DualShock 3 не тестировался: поддержка проверена mock-устройством
`tests/ps_mock.py` (цифровые триггеры и `BTN_DPAD_*`).

## Конфиг

Правьте `~/.config/gpadmapper-cpp/config.toml` и перезапускайте сервис:

```sh
systemctl --user restart gpadmapper-cpp
```

Полный файл с комментариями — [`config.example.toml`](config.example.toml).
Парсер понимает подмножество TOML: секции, `key = value`, строки в кавычках,
числа, `true`/`false`, комментарии `#`. Неизвестные ключи игнорируются.

### Действия кнопок

Действие — это:

- кнопка мыши: `BTN_LEFT`, `BTN_RIGHT`, `BTN_MIDDLE`, `BTN_SIDE`, `BTN_EXTRA`;
- любая `KEY_*`, например `KEY_ENTER`;
- комбинация через `+`, например `KEY_LEFTALT+KEY_TAB`;
- `none`, чтобы отключить кнопку.

Имена кнопок геймпада: `BTN_A`, `BTN_B`, `BTN_X`, `BTN_Y`, `LB`, `RB`, `LT`,
`RT`, `SELECT`, `START`, `MODE`, `THUMBL`, `THUMBR`, `DPAD_UP`, `DPAD_DOWN`,
`DPAD_LEFT`, `DPAD_RIGHT`.

## Прокрутка: `touchpad` и `wheel`

```toml
[scroll]
mode = "touchpad"   # по умолчанию: плавный жест
# mode = "wheel"    # обычное REL_WHEEL / REL_HWHEEL
```

**`touchpad` (по умолчанию).** Демон создаёт второе виртуальное устройство
`gpadmapper-scroll` с двумя MT-слотами. Левый стик двигает два «пальца», libinput
превращает это в непрерывный `POINTER_SCROLL_FINGER`, который все тулкиты
рисуют плавно. Скорость откалибрована так, чтобы `max_speed` означал то же
число щелчков колеса в секунду, что и в wheel-режиме
(`TP_UNITS_PER_NOTCH = 115`). Колесо на виртуальной мыши в этом режиме не
включается.

**`wheel`.** Виртуальный тачпад не создаётся, мышь шлёт `REL_WHEEL`,
`REL_HWHEEL` и hi-res варианты при `hi_res = true`. Для X11 или если
эмуляция тачпада не подходит.

### Две неочевидные детали

Обе — про «хвост» жеста. После возврата стика в центр демон не поднимает
пальцы сразу:

1. Оба пальца стоят неподвижно **300 мс**. Chromium считает скорость fling по
   времени между последним движением и `axis_stop`; если разрыв больше 200 мс,
   скорость нулевая и инерция не запускается.
2. Снимается второй палец, первый остаётся ещё на **250 мс**. Если поднять их
   вместе, libinput распознает двухпальцевый тап, а `tap_to_click` превратит
   его в правый клик.

Если стик снова выйдет из мёртвой зоны в эти 550 мс, тот же жест продолжится
без разрыва. Константы — в начале `gpadmapper-cpp.cpp`: `TP_FLING_GUARD`,
`TP_TAP_GUARD`, `TP_UNITS_PER_NOTCH`.

## Настройка стиков

Отклик радиальный:

```
magnitude = hypot(x, y)
strength  = ((magnitude - deadzone) / (1 - deadzone)) ^ curve
```

- `deadzone` — отклонение меньше этого игнорируется, остальное растягивается
  в 0..1;
- `curve` — `1` линейно, больше `1` точнее у центра;
- `max_speed` — пикселей в секунду для курсора или щелчков в секунду для
  прокрутки; в режиме тачпада калибровка сохраняет ту же физическую скорость.

Мёртвые зоны по умолчанию (`0.06` для курсора, `0.10` для прокрутки) замерены
на hall-effect стиках 8BitDo Ultimate 2C: в покое оси дают ровно `0`/`-1`,
`flat` ядра — 128 из 32768 (0.39 %), `fuzz` — 16 (0.05 %). Запас есть, но
центр не «вязкий». Если стики дрейфуют, увеличьте зону.

## Тесты

```sh
make test              # selftest в обоих режимах прокрутки
./gpadmapper-cpp --selftest
```

`--selftest` создаёт виртуальные устройства, подаёт синтетический вектор стика
и проверяет, что на выходе есть движение курсора или тачпада. Реальный геймпад
не нужен. Код возврата 0 — успех.

`make test` дополнительно прогоняет `tests/ps_mock.py`: mock DualShock 3 и
DualSense без физического контроллера проверяют кнопки, цифровые и аналоговые
триггеры, обе схемы крестовины (включая смешанную HAT + `BTN_DPAD_*`) и
удержание одной клавиши двумя кнопками. Нужен `python-evdev` и доступ к
`/dev/uinput`; без `python-evdev` этот шаг пропускается.

Флаги:

```
gpadmapper-cpp [-v] [--selftest] [--config PATH] [--device PATH]
```

- `-v` — печатать найденное устройство и каждое нажатие;
- `--config PATH` — другой конфиг;
- `--device PATH` — конкретный `/dev/input/eventN` вместо автопоиска.

## Если что-то не работает

- **`permission denied` на `/dev/uinput` или `/dev/input/event*`** — добавьте
  пользователя в группу `input` (см. «Зависимости») и перелогиньтесь.
- **Геймпад не найден** — запустите `gpadmapper-cpp -v`, он печатает
  кандидатов. Для отладки можно закрепить устройство через `--device`. Номера
  event меняются после переподключения, поэтому демон ищет по имени.
- **Прокрутка ступеньками** — вы в `wheel`-режиме или клиент игнорирует
  hi-res колесо. Переключите `mode = "touchpad"`.
- **Ложный ПКМ или инерция** — проверьте, что запущен свежий бинарник: обе
  защиты находятся в «хвосте» жеста тачпада.
- **Геймпад не работает в игре** — при `grab = true` он скрыт от игр. Оставьте
  `grab = false`, если не нужен монопольный захват.

## Производительность

Замер на машине разработки (8BitDo Ultimate 2C, Wayfire):

- RSS: ~4 МБ
- CPU в простое: 0.0 %
- CPU при полном отклонении обоих стиков: 0.6 %
- Размер бинарника: ~150 КБ

Геймпад отдаёт события примерно на 1 кГц, демон интегрирует на 250 Гц
(`TICK = 0.004`). Реальные тачпады работают на 100–125 Гц, так что 250 Гц
добавляют не больше ~4 мс задержки. Если видно «ступеньки» в движении
курсора, поменяйте `TICK` на `0.002` (500 Гц) и пересоберите.
